# 现场演示手册（Gradio）

老师的建议是"稳定能跑比野心大但演示崩溃好得多"。这份手册的目标就是：**任何一个环节出问题，都有下一个备用方案能接上。**

| 优先级 | 方案 | 依赖 |
|---|---|---|
| 1 | `--share` 公网链接，同学用手机扫码试用 | 外网 + Gradio 的转发服务 |
| 2 | 同一 Wi-Fi 下用局域网 IP 访问 | 教室 Wi-Fi 允许设备互访（或用手机热点） |
| 3 | 只在讲台电脑上演示 | 只要 Mac 本身能跑 |
| 4 | 播放提前录好的视频 | 什么都不依赖 |

## 一键启动（推荐）

在访达里双击 `cdt503/launch_demo.command`（交付文件夹里叫 `启动演示.command`）。它会：

1. 检查模型权重在不在、演示是不是已经开着、有没有别的模型程序占 GPU
2. 启动演示（同时开公网链接和局域网访问），预热完成后**自动打开网页**
3. 自动打开一个**扫码页**（大二维码）：拿到公网链接就用公网链接；网络拦截时自动换成局域网地址（同学要连同一个 Wi-Fi）
4. 终端窗口里显示本机、公网、局域网三个网址和运行日志

停止：关掉那个终端窗口，或按 Control + C。

页面只有浅色版：手动打开时网址后面加 `?__theme=light`（例如 `http://127.0.0.1:7860/?__theme=light`）；不加也行，深色模式的设备会自动跳到浅色版。第一次双击如果系统提示"无法打开"，在文件上右键 → 打开 → 打开。

## 启动命令（手动）

在项目根目录 `~/claude/review-lora` 下运行。默认加载第 1 阶段调参选出的最优模型（lr=5e-5，第 240 步）：

```bash
uv run python cdt503/app_gradio.py --share
```

- 启动时先加载模型并预热（约 20–30 秒），终端出现 `预热完成` 和网址后才开放网页
- `--share` 会额外打印一个 `https://xxxx.gradio.live` 公网链接，有效期 1 周
- 想换模型时加 `--adapter <目录>`，例如 `--adapter adapters_best`（调参前的第二版模型）

局域网备用方案（`--share` 失败时）：

```bash
uv run python cdt503/app_gradio.py --host 0.0.0.0
```

查本机 IP，同学在手机浏览器打开 `http://<IP>:7860`：

```bash
ipconfig getifaddr en0
```

在终端里打印网址的二维码，投到屏幕上让同学扫：

```bash
uv run --with qrcode python -c "import qrcode,sys; q=qrcode.QRCode(); q.add_data(sys.argv[1]); q.print_ascii(invert=True)" "http://$(ipconfig getifaddr en0):7860"
```

## 现场说明要点

- 页面上左边是原始模型、右边是微调后：**重点看左边的 "Invalid output" 和具体原因**，这是微调最直观的效果
- 点 Analyze 后是分步出结果的：左边先显示 "Base model is reading…"（原文上有光带扫过），左边出结果后右边再开始扫。这反映的是真实顺序——同一个模型先不带适配器答一次，再带适配器答一次；可以边等边说 "first without our adapter, now with it"
- 人多时每个人会先看到 "Waiting in line — n requests ahead of you"，轮到自己才开始扫描
- 一次只处理一个请求，其他人排队。实测每个请求约 4 秒（原始模型和微调后各生成一次）；
  12 人同时点时，第 12 个人要等约 50 秒，全部成功、没有出错。全班 30 人同时用，最后一个人约等 2 分钟——
  可以提前告诉同学"人多时要排队"，或者请大家分批试

## 示例与预期结果

页面上的 8 个示例按演示顺序排列（2026-10-29 用 lr=5e-5 实测）。1–3 是真实评论，来自第 2 阶段人工标注的 100 条。

| # | 示例 | 原始模型 | 微调后 | 讲解要点 |
|---|---|---|---|---|
| 1 | 果子特别棒没有伤比超市便宜又好吃 | ✗ 编出列表外的方面"味道" | 口味口感 +、价格 + | 原始模型不守规则，程序没法用 |
| 2 | 乐视会员卡没有收到……相机真的很垃圾 | ✗ 编出"产品" | 服务 −、使用效果 − | 同上；差评也能拆成两个具体方面 |
| 3 | 升级完7.0系统，挺流畅的，就是耗电有点快…… | ✗ 情感答"中性" | 使用效果 + | 褒贬混合时原始模型会发明"中性" |
| 4 | 酒店离地铁站很近……隔音很差，前台……等了半小时 | ✗ 情感答"中性" | 位置交通 +、房间设施 −、服务 − | 一条评论拆出三个方面 |
| 5 | 苹果个头很大，脆甜多汁，就是有两个磕坏了…… | 只找到 1 个方面 | 尺寸、口味、故障、包装 4 个 | 微调后抽得更完整 |
| 6 | 还没用，用了再来评价 | ✗ 情感答"中性" | 没有具体方面 | 刁钻：什么都没说时不乱抽 |
| 7 | 收到就是坏的，开不了机，客服一直推脱不给换 | 故障瑕疵 −（漏了服务） | 故障瑕疵 −、服务 − | 原始模型会漏 |
| 8 | 好评！用了三天就坏了，质量真是"好"啊 | 故障瑕疵 − | 故障瑕疵 − | 反讽：两个模型都识别对了，诚实地说"不是每条都有差距" |

模型输出是确定的（每次都选概率最高的字），同一台电脑、同一个检查点，结果每次都一样。如果现场结果和上表不同，先检查加载的是不是 `cdt503/runs/sweep/lr5e-5/best`（终端第一行会打印）。

## 商品报告页（Product report）

页面最下面的 Product report 区：粘贴一批评论（一行一条）、上传 CSV/TXT，或点上传框下面的示例文件（Hotel / Tablet / Fruit，各 150 条没用过的评论；点一下就装进上传框，点文件名旁的 ↓ 能下载下来看格式），
点 Generate report，模型逐条分析后给出：好评/差评比例、最受好评和最常被抱怨的方面、每个方面的好差评次数和原文观点、
条形图，以及逐条结果 CSV 下载。

- 150 条约 2 分钟（每条约 0.75 秒），有进度条；生成期间别人的单条请求会在两组之间插队，不会卡死
- 预期结果（2026-11-18 离线实测，和网页一致；明细在 `cdt503/results/product_report/<样例>/`）：

  | 样例 | 好评（星级） | 整体判断与星级一致 | 最受好评 | 最常被抱怨 |
  |---|---|---|---|---|
  | Hotel | 53%（55%） | 93% | 房间设施 53、位置交通 45、服务 37 | 房间设施 71、服务 35、价格 24 |
  | Tablet | 49%（50%） | 96% | 使用效果 54、物流 13、价格 10 | 使用效果 33、故障瑕疵 16、服务 15 |
  | Fruit | 41%（45%） | 95% | 口味口感 45、物流 25、价格 13 | 故障瑕疵 43、尺寸重量 38、口味口感 33 |

  原数据集每类都是人为凑成好差评各半，所以好评率本身没意义，看的是和星级的一致程度
- **不能和训练同时开**：报告是批量生成，和训练叠加会 GPU 内存不足，两边一起崩（11-17 实际发生过）
- 现场建议只由讲台电脑演示这一段，内置示例文件最稳：**上台前另开一个浏览器标签页，在它的报告区点 Hotel 示例文件、生成好报告**，演示时切过去讲，不现场等 2 分钟；第一个标签页留在页面顶部，开头的动画留给观众看（见 `presentation/demo_script.md`）

## 录制备用视频

1. 正常启动演示，浏览器全屏
2. 按 ⌘ + Shift + 5，选"录制所选部分"，框住浏览器窗口；"选项"里麦克风选"无"
3. 依次演示：普通正面例子 → 褒贬混合例子 → 两个刁钻例子 → 自己现场打一条
4. 每个例子停留 5 秒左右，让观众看清左右对比；总长控制在 1.5 分钟以内
5. 再按一次 ⌘ + Shift + 5 停止，视频默认存在桌面。用 QuickTime 打开检查一遍

## 常见问题

| 现象 | 处理 |
|---|---|
| 终端报 `Insufficient Memory` | 有别的模型程序在占 GPU。用 `pgrep -fl python` 找到并关掉，重新启动演示 |
| `Address already in use` | 7860 端口被占用。加 `--port 7861` 换一个端口 |
| `--share` 一直没有出现公网链接 | 网络拦截了转发服务。改用局域网方案或热点 |
| 同学手机打不开局域网地址 | 教室 Wi-Fi 禁止设备互访。电脑和同学都连你的手机热点 |
| 页面提示 "still warming up" | 预热还没完成，等终端出现 `预热完成` 再用 |
| 页面提示 "Something went wrong" | 单次请求出错，程序本身不会崩，直接再点一次 Analyze |
| 一切都不行 | 播放备用视频，同时用讲台电脑展示报告里的截图 |
